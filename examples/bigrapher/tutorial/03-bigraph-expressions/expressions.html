Bigraph Expressions

The five declarations in expressions.big are built from three products and one composition. For each declaration this page gives its algebraic form, its type, its place and link graphs, and the drawing BigraphER makes of it.

Reading the notation

G : I → J
“G has type I → J.” I is the inner face, what G needs from inside. J is the outer face, what the rest of the model sees.
⟨m, X⟩
An interface: m places (sites on the inside, regions on the outside) and a set X of names. Name sets are green because names belong to the link graph.
ε = ⟨0, ∅⟩
No places and no names. A bigraph ε → J has no sites, so it is ground. Every bigraph in expressions.big is ground.
F ∘ G
Put G inside F: the regions of G fill the sites of F. Defined only when the outer face of G equals the inner face of F. Read right to left. BigraphER writes F * G.
A ⊎ B
Disjoint union: A ∪ B when A and B share nothing, undefined when they overlap. Its size is always |A| + |B|, while A ∪ B can be smaller.
Kx.1
A node with control K whose port links to the name x, with nothing inside it. 1 : ε → ⟨1, ∅⟩ is one empty region. BigraphER writes K{x}.1.
prnt, link
prnt : m ⊎ V → V ⊎ n gives the parent of each site and node. link : X ⊎ P → E ⊎ Y sends each inner name and port to an edge or an outer name. (v, i) is port i of node v.

Reading the drawings

  • Region (root), numbered from 0. Its position on screen means nothing; the number does.
  • Site, a hole another bigraph can fill. None of the drawings here have one.
  • Node, labelled with its control.
  • Place graph: from parent to child.
  • Link graph: lines that meet form one link.
  • Outer name, at the top of the drawing.

Hover over a green line to see its edge and the nodes it joins, for example e0: {v0,v1}.

Three products

Take two bigraphs G0 : ⟨m0, X0⟩ → ⟨n0, Y0⟩ and G1 : ⟨m1, X1⟩ → ⟨n1, Y1⟩ with no nodes or edges in common. All three products have the same inner face, ⟨m0 + m1, X0 ⊎ X1⟩. They differ only in the outer face: how many regions the result has, and what happens to an outer name both sides use.

ProductBigraphEROuter faceShared outer namesRegions
G0 ⊗ G1 + ⟨n0 + n1, Y0 ⊎ Y1⟩ rejected kept apart
G0 ∥ G1 || ⟨n0 + n1, Y0 ∪ Y1⟩ joined into one link kept apart
G0 | G1 | ⟨1, Y0 ∪ Y1⟩ joined into one link merged into one

The bold cell in each row is what that product adds to the one above it. Tensor also needs disjoint inner names.

Built in two steps

G0 ∥ G1 = (idn0+n1 ⊗ σ) ∘ (G′0 ⊗ G′1)

G0 | G1 = (mergen0+n1 ⊗ idY0∪Y1) ∘ (G0 ∥ G1)

For ∥, G′0 and G′1 are copies of the operands with each shared outer name y renamed apart (BigraphER uses 0y and 1y). The tensor of the copies is then defined, and the substitution σ sends 0y and 1y back to the single name y. The place graph is the same as for ⊗.

For |, mergen : ⟨n, ∅⟩ → ⟨1, ∅⟩ has no nodes and puts all n of its sites in root 0. Composing with it moves every top-level node into one region and leaves the links as they were.

Checking the type of G0 | G1

G0 ∥ G1: ⟨m0+m1, X0 ⊎ X1⟩→ ⟨n0+n1, Y0 ∪ Y1⟩ mergen0+n1 ⊗ idY0∪Y1: ⟨n0+n1, Y0 ∪ Y1⟩→ ⟨1, Y0 ∪ Y1⟩ G0 | G1: ⟨m0+m1, X0 ⊎ X1⟩ → ⟨1, Y0 ∪ Y1⟩

Read ∘ right to left, so G0 ∥ G1 comes first. The highlighted faces match, so the composite is defined. Its type keeps the inside of the first step and the outside of the last.

  • On ground bigraphs, | does not depend on order: G | H = H | G, because merging discards the region numbers. G ∥ H and H ∥ G differ in which operand gets region 0.
  • BigraphER’s || also accepts shared inner names. It joins the links that each side’s copy of the name feeds.

The model, declaration by declaration

t: ε → ⟨2, ∅⟩

big t = P.1 + Q.1;
Algebra
t = P.1 ⊗ Q.1
Nodes
V = {v0 : P, v1 : Q}
Place graph
prnt : v0 ↦ 0, v1 ↦ 1
Link graph
Empty. P and Q have no ports.

Tensor puts P in region 0 and Q in region 1. Neither control has ports, so neither side has names and the tensor’s condition of disjoint names holds trivially.

c: ε → ⟨2, ∅⟩

big c = id(2) * t;
Algebra
c = id2 ∘ t
Type check
t : ε → ⟨2, ∅⟩
id2 : ⟨2, ∅⟩ → ⟨2, ∅⟩
id2 ∘ t : ε → ⟨2, ∅⟩
Graphs
Same nodes, parents and links as t.

BigraphER writes composition (∘) as *. id(2) has two sites and two regions and puts site i in region i. The composite is defined because the outer face of t, ⟨2, ∅⟩, equals the inner face of id2. The identity changes nothing, so c is the same bigraph as t and the two drawings match.

p: ε → ⟨1, {x}⟩

big p = A{x}.1 | B{x}.1;
Algebra
p = Ax.1 | Bx.1
  = (merge2 ⊗ id{x}) ∘ (Ax.1 ∥ Bx.1)
Nodes
V = {v0 : A, v1 : B}
Place graph
prnt : v0 ↦ 0, v1 ↦ 0
Link graph
link : (v0, 0) ↦ x, (v1, 0) ↦ x

A and B become siblings in region 0. Both ports use the name x, so the parallel step inside | joins them into one link. The drawing shows it as one green hyperedge running to x.

pp: ε → ⟨2, {y}⟩

big pp = C{y}.1 || D{y}.1;
Algebra
pp = Cy.1 ∥ Dy.1
Nodes
V = {v0 : C, v1 : D}
Place graph
prnt : v0 ↦ 0, v1 ↦ 1
Link graph
link : (v0, 0) ↦ y, (v1, 0) ↦ y

C and D keep separate regions, as they would under +. The name y appears on both sides, which + rejects. || takes the union of the outer names, {y} ∪ {y} = {y}, so both ports land on one link.

init_state: ε → ⟨1, {x, y}⟩

big init_state = p | pp | c;
Algebra
init_state = (p | pp) | c
  = (merge5 ⊗ id{x,y}) ∘ (p ∥ pp ∥ c)
Type check
p ∥ pp ∥ c : ε → ⟨1+2+2, {x, y}⟩
merge5 ⊗ id{x,y} : ⟨5, {x, y}⟩ → ⟨1, {x, y}⟩
Nodes
V = {v0 : A, v1 : B, v2 : C, v3 : D, v4 : P, v5 : Q}
Place graph
prnt : v ↦ 0 for every v ∈ V
Link graph
link : (v0, 0), (v1, 0) ↦ x; (v2, 0), (v3, 0) ↦ y

| merges every region its operands bring. p has 1, pp has 2 and c has 2, so five regions become one, and the separation that || and + made inside pp and c is gone. BigraphER reads p | pp | c as (p | pp) | c. Merging twice gives the same result as merging once, which is the second line of the algebra.

To keep the regions apart in the initial state, write big init_state = p || pp || c;. Here p + pp + c also gives five regions, because p, pp and c share no names.

Nesting needs one region

R.(C{y}.1 | D{y}.1)Accepted R.(C{y}.1 || D{y}.1)Error: Interfaces <1, {y}> and <2, {y}> do not match in the composition

With ctrl R = 0, R.G places G in the single site of R, so the context’s inner face is ⟨1, {y}⟩. The merge product’s outer face, ⟨1, {y}⟩, matches. The parallel product’s, ⟨2, {y}⟩, does not: two regions cannot fill one site. This is what | is for. It turns several places into one place you can nest.

Regenerating the drawings

From this folder:

nix-shell ../../../../shell.nix
mkdir -p out
bigrapher validate -d out -f svg expressions.big

validate -d writes one drawing per big declaration. Use -f svg,json,txt to also get BigraphER’s structured output, which is where the node numbers and links above come from. Create out first: when the folder is missing, BigraphER reports `dot' command not found even though Graphviz is installed.

The drawings of C{y}.1 | D{y}.1 and p || pp || c come from a scratch copy of the model with two extra declarations, so expressions.big is unchanged. This page is a snapshot and does not update when the model changes.
